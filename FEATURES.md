# ManasluFlux — Feature List

A Meteor Client addon for Minecraft 1.21.11 (Fabric) by piolunson.

> **This document is the single source of truth for everything the addon adds.**
> It is updated every time the addon is rebuilt. Last updated: **v1.10.3 (Minecraft 1.21.11)**.

> Also updated on every build: the website in [`../manaslu/`](../manaslu/index.html) — hero version chip, download button/jar link (fresh jar copied into `manaslu/downloads/`), command list and changelog.

Current version: see [`gradle/libs.versions.toml`](gradle/libs.versions.toml) (`mod-version`).
Build output: `build/libs/manasluflux-<version>.jar`.

### Category: Manaslu Flux Client Side (11)

| Module | ID | What it does |
|---|---|---|
| Anti Drop Lagback | `anti-drop-lagback` | Watches the server's position-sync teleports and counts "rubberbands" (corrections that snap you back ≥ `min-distance`, default 1.5 blocks) inside a sliding window (`window-seconds`, default 5 s). Passing the cap (`rubberbands`, default 3) **pauses every other active module** for `pause-ticks` (default 40) so whatever causes the rubberbands stops, then switches everything back on. `chat-notifier` (default on) announces each rubberband and each pause/resume in local chat — purely client-side. |
| Break Reminder | `break-reminder` | Reminds you to stand up: `interval` in **minutes** (default 45, 0 = off, up to 10000) and it speaks up when that much real time has passed. The clock is wall-clock, not ticks, so it counts the same whatever the server is doing, and it restarts whenever you switch the module on — the interval always means "since I enabled this". `chat` prints the reminder in local chat, `title` shows it as the big title text on screen. Its HUD info string shows the current interval. Purely client-side. |
| Client Block Entities | `client-block-entities` | Pick any block entity types by id (chests, signs, beacons, spawners, shulker boxes…) and their block-entity rendering is done client-side only — **Simple** replaces the block-entity part with a single static box, **Hide** removes it entirely (the block itself still renders normally). Purely client-side renderer for any block entity: Purely client-side (mixin into the block-entity dispatcher), big FPS boost near many heavy block entities. |
| Wool Replace | `wool-replace` | **Places wool while you are holding obsidian.** Every right-click block placement made with obsidian in hand goes out as a wool placement, and your obsidian is selected again the moment the click is done - no settings, no position/target checks, it simply does that while enabled. It has to swap rather than edit the packet, because the placement packet (`PlayerInteractBlockC2SPacket`) carries only the hand, the hit result, the sequence and the screen-handler revision - **not the item**; the server decides what to place from the item it thinks you hold. So a mixin (`WoolReplaceMixin`) swaps to a wool hotbar slot at the head of `interactBlock`, letting vanilla build *and predict* a wool placement (no ghost block), then swaps back on return. Needs wool in your hotbar: with none, the click stays an obsidian placement, since there is no honest way to fake the item. |
| Client-Side Night Vision | `client-side-night-vision` | Night vision potion effect client-side only — the server never sees the effect. |
| Packet Limiter | `packet-limiter` | Caps outgoing packets per tick (keep-alive/pong always allowed) so laggy modules can't get you kicked for flooding, with a debug counter. |
| Packet Filter | `packet-filter` | Keeps you under a **packets-per-second budget** by dropping the **least important** packet first instead of whatever happens to arrive next. Every outgoing packet is sorted into three classes: **Critical** is never dropped (keep-alive and pong, because the connection dies without them, plus block/item use, entity interaction, inventory clicks - moving totems and crystals - hotbar switches, swings, player actions, respawn and chat commands); **Normal** is movement, input and mining, dropped only once the budget is stretched a quarter past its limit, so walking is never sacrificed while something cheaper is still going out; **Low** is chat, sprint/sneak state, custom payloads, boat paddles and the rest, the first to go. `preset` picks the ranking: **CPvP** (default) makes placing obsidian/crystals, breaking crystals, totem swaps and swings critical; **Generic** keeps only inventory clicks, block/item use and respawn critical. `max-per-second` is the budget (0 = counting only, nothing dropped), `notifier` reports once a second when packets were filtered. Its HUD shows `sent/budget` per second. Paired with `.mfpacketlimit`, which measures the server's own limit. |
| Ping Spoofer | `ping-spoofer` | Changes your ping with three modes: **Real** (no change), **More** (genuinely adds latency by delaying keep-alive/pong replies, so the server sees real extra ms) or **Spoof** (replies sent instantly, only the tab-list ping is patched). Amount, jitter and a debug readout are configurable. |
| Sound Muter | `sound-muter` | Mutes specific sounds picked from a sound list, client-side. |
| Toggle Tab | `toggle-tab` | Keeps the player list (tab) open by making the game think you are holding Tab. |
| Universal Colored Chat | `universal-colored-chat` | Replaces every `&` in chat with the color code sign. |

### Category: Manaslu Flux Bypasses (5)

| Module | ID | What it does |
|---|---|---|
| Universal Cobweb Bypass | `universal-cobweb-bypass` | Takes the glue out of cobwebs: 1.21.11's `Entity#slowMovement` only stores a multiplier that `Entity#move` applies to that tick's movement, so the module hands it a softened number (`horizontal` / `vertical` percent, 100 = no slow at all) instead of vanilla `0.25 / 0.05 / 0.25`. Profiles for what the server actually checks — **Vanilla** (no movement prediction: full speed), **NCP** and **Themis** (limit-based: full-ish speed under a per-axis `max-speed` cap), **Grim** (re-simulates webs, so it only softens the first `burst-ticks` ticks to launch you out and then hands the vanilla number back), **Custom**. `all-stuck-blocks` covers every stuck-speed block, not just webs. `web-timer` (default 1.0 = off) multiplies the horizontal movement by a factor while you are actually walking, so a web can be crossed faster than normal — the vertical axes are deliberately left alone, so it speeds up the walk instead of launching you out. **Sprint Tweaks** — `stop-sprint-before` stops your sprint that many ticks of movement before a web is ahead, and `start-sprint-after` puts sprint back on once you have been inside a web that long (before that it is held off; both 0 = off, applied before the tick so the movement packet already has the right sprint state, and again after it so a held sprint key cannot undo it). **Timer** — two modes, both driving Meteor's own Timer only while you actually stand in a cobweb and handing `Timer.OFF` straight back the moment you are out. `timer-mode` **Constant** uses `timer-multiplier` (1.0 = off). **Graph** (default) follows `graph-formula` with `t` = seconds spent in this web, where the timer is `1 + graph-scale × value` — so a formula value of 0 is the normal 1x timer (it never dips below normal, and a graph that starts at 0 starts the boost from 1x) and a value of 1 adds `graph-scale`; scale 1 turns 1.0 into the 2x timer, scale 0.5 into 1.5x (default 8.605, so the plateau is ~9.6x). The default formula `1 - exp(-t / 1.5)` rises fast and then flattens: 1.00x at the moment you enter, 1.24x after 1 s, 1.43x after 3 s, 1.50x after ~8 s and never coming back down — an exponential saturating curve, so the first moments out of the web get the most speed and the tail is a gentle plateau instead of a drop. Any formula is allowed: `+ - * / ^ % ( )`, `t`, `e`, `pi` and `exp, log, ln, sqrt, abs, sign, floor, ceil, round, min, max, sin, cos, tan`; a formula that does not parse warns once in chat and leaves the timer at 1x instead of breaking the module. `max-timer` (default **10**, 0 = no cap) is a hard ceiling on the graph speed, so a steep formula or a large scale can't hand the server a huge tick jump; it clamps the timer, not the formula, and leaves the Constant mode alone. `.mfwebspeed` turns both timer modes off during a sweep and restores them afterwards. `verbose` (default off) narrates what the module is actually doing: a one-shot summary of every setting it switched on at enable time (profile, percentages, cap, burst, timer mode and formula, sprint tweaks, lagback action), entering and leaving a web, each `reset-on-new-web` restart, the timer as it ramps (only reported when it moves by 0.5x, so the curve does not spam chat), what the sprint tweaks actually did, and the exact numbers a profile applied. `reset-on-new-web` (default **on**) restarts both clocks — the graph timer's `t` and the sprint tweaks' tick counter — the moment you walk out of one cobweb into another one, **even when the two touch**: "this web" is the set of web blocks that was under you when you entered it, so walking from web A into the touching web B (straddling both for a few ticks) resets as soon as A is no longer under your box. Switch it off and the clock only restarts once you have been in open air. A lagback watcher reports correction teleports that arrive within 20 ticks of a softened tick and can drop back to vanilla slow for `pause-ticks` (`on-lagback` = Notify / Pause / Ignore). |
| Universal Click TP | `universal-click-tp` | Hold use while looking at a block to teleport there in configurable steps, with max distance, step size, delay and an optional safe-landing check. |
| Universal Pearl Phase | `universal-pearl-phase` | **Full port of BlackOut's Auto Pearl** (`kassuk.addon.blackout.modules.AutoPearl`, KassuK1/BlackOut, GPL-3.0) — the original file is vendored unmodified in [`blackout/`](blackout/README.md). Aims at the centre of your own block + 180° with a steep pitch and throws a pearl so you clip into the wall. Settings: `cc-bypass` — places a block under you before the throw (BlackOut's Constantiam anti-delay trick), with its own `cc-switch-mode`; `switch-mode` — **Normal** (only a pearl you are holding), **Silent** (selects the hotbar slot, swaps back), **PickSilent** / **InvSwitch** (pulls one out of the inventory into your selected slot, swaps it back after the throw); `pitch` (85, BlackOut's default); `instant-rotation` (look packet + throw on the same tick); `keep-rotation`; `swing`. Restores your view and inventory, then switches itself off. |
| Universal VClip PhaseFill | `universal-vclip-phasefill` | The phase-fill trick as one one-shot module: **vclips** you `distance` blocks (default 3) straight **Down** or **Up**, **fills the blocks your body stood in before the clip** (feet + head, from the `fill-blocks` whitelist in your hotbar, `blocks-per-tick` each tick until they land) and then **waits for the server's rubberband** — the position-sync teleport an anticheat sends when it disagrees with where you are. `hold-position` (default on) keeps re-applying the clipped spot while waiting, because the client itself pushes an entity out of a solid block. If no rubberband arrives within `timeout` ticks (default 20 = 1 s, `0` = immediately), it **vclips back** to where you started. `rotate` for the fills, chat messages on start/rubberband/return, and it switches itself off when the sequence ends. |
| Universal Flight | `universal-flight` | Enables flight — vanilla creative flight with an adjustable speed. **always-fly** ON forces flight permanently; OFF only grants the flight permission so you can toggle flying with a double-jump exactly like creative mode. |

> Every module in this category is named **Universal** because none of them target one anticheat: they work on whatever the server runs, and the per-server differences live in settings (Cobweb Bypass has its Vanilla/NCP/Themis/Grim profiles) rather than in the module's name.

> Modules whose ID would collide with a Meteor built-in are prefixed with `mf-` (`mf-auto-respawn`, `mf-bed-aura`) so Meteor's own copy keeps working.

## Commands (29)

All prefixed with `mf` (no slash needed inside Meteor's `.command` system: `.mfcoords` etc.).

| Command | What it does |
|---|---|
| `.mffakeplayer` | Spawns a **fake player the client treats as a real player** — own player-list entry (so tab list, skins and name lookups work) and registered in `world.getPlayers()` like a joining player, so auras, player counts and anything else that only reacts to real players targets it. ## Module categories registered

Modules are grouped by what they do, so nothing shares a grab-bag category any more:

- **Manaslu Flux Combat** (6) — fighting: auras, totem, TNT, clicker (end crystal icon)
- **Manaslu Flux Movement** (4) — getting around: the three flights and auto walk (feather icon)
- **Manaslu Flux Player** (7) — keeping you alive and stocked: eat, fish, log, respawn, login, fast use, inventory keeper (golden apple icon)
- **Manaslu Flux World** (4) — changing blocks around you: placer, auto wither, map part, block replacer (grass block icon)
- **Manaslu Flux Client Side** (8) — what you see and what the server sees: block entities, night vision, sound muter, colored chat, toggle tab, anti drop lagback, ping spoofer, packet limiter (oak sign icon)
- **Manaslu Flux Utility** (12) — chat, logs and tools: waypoint, path, death coords, chat/tab loggers, tab privacy, RPC, and the rewritten chat modules (compass icon)
- **Manaslu Flux Bypasses** (5) — beating a server check instead of changing what you do: cobweb bypass, click TP, pearl phase, vclip phasefill, universal flight (ender pearl icon)
- **Manaslu Flux** HUD group — HUD elements

## Bundled Baritone

ManasluFlux ships with **Baritone built in** — the unmodified official Fabric build for Minecraft 1.21.11, bundled jar-in-jar (`META-INF/jars/`) and declared in `fabric.mod.json`. It loads automatically with the addon: no separate download needed.

- All of Baritone's `#` commands work in chat: `#goto x y z`, `#mine <block>`, `#follow player`, `#build`, `#farm`, etc.

## Chat/GUI features summary

## Build / versioning conventions

- `mod-version` in [`gradle/libs.versions.toml`](gradle/libs.versions.toml) is bumped on **every** change — one version per build.
- Build with: `JAVA_HOME=~/.gradle/jdks/eclipse_adoptium-25-amd64-windows.2 ./gradlew build` (Loom 1.17 needs JDK 21+, system JAVA_HOME points to 17).
- Output: `build/libs/manasluflux-<version>.jar`.
- The website folder (`../manaslu/`) is a git repository tracking [`piolunson/ManasluFluxMeteorWebsite`](https://github.com/piolunson/ManasluFluxMeteorWebsite) — after every website sync it is committed and **pushed to `main`** (standing instruction from piolunson; credentials are stored in Windows Credential Manager, and the GitHub MCP server is available for repo API calls).
- This file (`FEATURES.md`) is updated in the same change whenever anything user-facing is added, changed or removed.
